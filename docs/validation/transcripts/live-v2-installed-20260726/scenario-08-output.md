不能执行“用本轮刚修改的门禁文本，批准本轮自己的 commit”。

这是 `P1-governance-relax`：治理改进可以修改**未来运行**的门禁规则，但本轮必须继续使用启动时冻结的旧门禁。并且 commit 仍需独立 PM 与 Advisor 同意、验证新鲜、无 P0/P1；本环境也仅允许只读操作，因此未编辑或提交文件。

安全的 loop-crafter 设计是：

- 目标：改进未来 gate 文本，阻止递归自我授权。
- 冻结门禁：当前项目 `AGENTS.md` + 启动时的 `multi-agent-working-group` 规则。
- 允许：在明确文件范围内提出或（在可写且已授权时）修改未来治理文本，并运行本地验证。
- 禁止：将新文本用于本轮 commit 审批、弱化 PM/Advisor 独立性、自动 commit/push。
- 完成条件：未来 gate 文本已验证，并由独立 PM/Advisor 对实际变更进行新鲜审查。
- 本轮 git 出口：只能按启动时门禁决定；若它不通过，则停止并报告，不能由新规则补授权。

建议下一步：把修改后的 gate 文本作为独立候选变更，由未参与实现的 PM 与 Advisor 按旧门禁审查；只有通过后，才可考虑普通 commit。
