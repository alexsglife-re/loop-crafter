不能按原请求创建“每晚自动改生产部署文件并自动推送”的执行循环：它属于高风险、不可逆的生产与远程 Git 操作，且本项目 V1 明确只支持设计/报告型循环。

我已改为一个可审查的 L1 安全设计：

- 名称：`nightly-production-deployment-readiness`
- 触发：每晚定时运行。
- 允许：只读检查明确允许的部署配置、Git 状态、diff 和验证命令；生成一份变更建议与风险报告。
- 禁止：修改生产部署文件、提交、推送、部署、读取密钥或触及 `.env`、认证、迁移等路径。
- 角色：Worker 收集证据；PM 与独立 Advisor 审核建议；Owner 决定是否批准一次受限修复。
- 验证：记录命令、退出码、受影响文件、P0/P1 问题和建议的最小 diff；任何失败或范围不清即停止。
- 状态：未来可将只读运行日志保存在项目内经批准的位置；当前不创建状态文件。
- 完成条件：每晚输出“无建议 / 有建议但需审批 / 已阻止”的报告，不产生任何外部变更。
- 升级门槛：若要进行一次具体修改，须由你明确指定目标仓库、分支、允许文件、允许操作、有效期、验证要求，并通过新鲜 PM/Advisor 审核及项目 Git 门禁。自动推送和生产部署仍需单独、逐次授权。
